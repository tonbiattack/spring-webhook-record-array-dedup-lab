# 題材重複調査レポート: Spring Webhookで`record`の`byte[]`により同一配信を重複処理する

## 調査対象

| 項目 | 内容 |
| --- | --- |
| 対象言語 | Java 21 |
| 難易度プロファイル | 実践・上級 |
| 候補題材 | Spring MVCのWebhook受信時、同じ内容・別参照の`byte[]`を持つrecordが`HashSet`で重複排除されない問題 |
| 観測可能な契約 | 同じJSONを二度POSTしたとき、二度目は`409`・最終件数は`1`であるべきだが、バグ状態では二度目が`202`・最終件数が`2`となる。 |
| 直接原因 | `byte[]`コンポーネントを持つrecordの自動生成`equals`／`hashCode`が、ペイロード内容による業務上の同一性を表現しないこと。 |
| カタログ更新日時 | Repository Catalog（`/home/ubuntu/repository-catalog`）は調査時点で存在しなかったため、更新・検証は実施不能。代替として、ユーザー指定の`tonbiattack/qiita`をローカル取得し、Java・Spring・配列・重複排除・Webhook・冪等性の語で本文とパスを検索した。 |
| 検索語 | `Java`, `Spring Boot`, `record`, `byte[]`, `配列`, `Webhook`, `HashSet`, `重複排除`, `冪等`, `イベント`, `キャッシュ` |

このレポートでいう「重複なし」は、既存記事との**原因・実境界・観測契約・最小修正**の四軸が一致しないことを意味します。Repository Catalogが利用できなかったため、すべてのローカル専用教材までは保証できないという限界があります。

## 近接候補の比較

| 既存コンテンツ | 既存の原因 | 既存の実境界・最終観測 | 今回の差分 | 判定 |
| --- | --- | --- | --- | --- |
| 「Spring Bootで価格検索が見つからない理由：BigDecimalの`equals`と`compareTo`を最小再現から理解する」 | `BigDecimal`の数値的同値とscaleを含む`equals`の差。 | `HashMap<BigDecimal, String>`で`1.00`検索が`null`となる。 | 今回は数値・scaleではなく、record内のバイナリ配列の内容同一性が原因である。実境界はHTTP POST、最終観測は処理済み件数、修正は正規化ではなく配列内容の`equals`／`hashCode`である。 | 重複なし |
| 「Javaで『同じ瞬間』のイベントが重複排除されない理由：`ZonedDateTime.equals`と`Instant`の契約を最小再現から理解する」 | ゾーンを含む値としての`equals`と、時間軸上の同一瞬間の差。 | `LinkedHashSet<ZonedDateTime>`で同一瞬間が二件残る。 | 既存は日時表現を`Instant`キーへ正規化する。今回はJSONで受信した`byte[]`を持つrecord、HTTP応答と最終カウント、配列内容比較の明示という別の原因・境界・修正である。 | 重複なし |
| 「JavaのByteBufferでflipを忘れて空文字列を保存するバグを実際にデバッグする」 | `ByteBuffer`の読み書き位置を切り替える`flip()`の見落とし。 | バッファから読み出した文字列が空になる。 | 配列を扱う近接語はあるが、今回の主題はバッファ状態遷移ではなく、recordの自動生成等価性と集合の重複判定である。 | 重複なし |
| 「冪等性とExactly-onceは同じではない：DB更新とイベント配信を安全にするTransactional Outbox」 | DB更新とイベント配信の整合性、分散システムの配送保証。 | 永続化・イベント配信の設計上の安全性を扱う。 | 今回は単一プロセス・インメモリ集合でのJava値オブジェクトの等価性だけを扱う。永続化、アウトボックス、配送保証、並行性は対象外である。 | 重複なし |

## 結論

**作成する。**

既存の`BigDecimal`および`ZonedDateTime`記事はいずれも「業務上の同一性」とJavaの`equals`を取り違える近接テーマですが、直接原因はそれぞれ数値scaleおよび時間表現です。今回の原因は**配列をrecordコンポーネントに置いたときの内容同一性の欠落**であり、既存のどちらとも異なります。

実境界も異なります。既存の近接記事はサービス関数またはコレクション処理を観測しますが、本教材はSpring MVCがJSONのBase64を`byte[]`へ変換するHTTP境界を通し、二度目のステータスと`processedCount()`の最終状態を独立して検証します。最小修正は、キーを正規化・変換することではなく、`Arrays.equals`と`Arrays.hashCode`を使ってrecordの同一性を明示することです。

同じ「重複排除」という名称だけを変えた再実装ではなく、バイナリペイロードを持つWebhook DTOという実務的な境界で、Javaのrecordと配列の落とし穴を独立して学べる題材と判断しました。
